# Блок 6. Отладка

После урока 30. Ты знаешь всё, что было в курсе: переменные, ветвления, функции, циклы, рекурсию, массивы — и теперь
умеешь пользоваться дебаггером IntelliJ IDEA.

Этот блок устроен не так, как остальные. В каждой заготовке `src/block6/TaskXX.java` уже лежит готовая программа.
Она компилируется и запускается, но работает неправильно (кроме задачи 6.7). Твоя задача — найти ошибку
**дебаггером**, а не угадать, перечитывая код, и исправить её.

Как работать:

1. Запусти программу обычным Run и сравни вывод с ожидаемым из условия.
2. Заранее посчитай на бумаге, какими должны быть значения переменных, — иначе в дебаггере не с чем будет сравнивать.
3. Поставь breakpoint, запусти Debug и иди по шагам, сверяя значения в Variables со своими.
4. Найди место, где поведение **впервые** расходится с ожидаемым: строку и значения переменных в этот момент —
   `i`, индекса, аргументов функции.
5. Исправь причину. Обычно это одна строка. Не подгоняй ответ: не прибавляй `+ 1` или `- 1` к результату,
   не меняй данные в массивах, не добавляй `if` под конкретный пример — программа должна работать на любых
   правильных данных, а не только на примере.
6. Внизу каждой заготовки есть шаблон ответа — заполни его комментариями. Номера строк указывай как в заготовке
   **до** исправления. Пункт «как увидел в дебаггере» — главный в этом блоке: что стояло в Variables, на какой
   строке ты остановился, что показали Frames или Evaluate.

Пользуйся только тем, что было в уроке 30:

| Действие | Windows / Linux | macOS |
|---|---|---|
| Поставить или снять breakpoint | Ctrl+F8 или клик слева от номера строки | ⌘F8 или клик слева от номера строки |
| Запустить в режиме отладки | зелёная стрелка у `main` → Debug | зелёная стрелка у `main` → Debug |
| Step Over — следующая строка | F8 | F8 |
| Step Into — войти в функцию | F7 | F7 |
| Step Out — выйти из функции | Shift+F8 | ⇧F8 |
| Resume Program — до следующего breakpoint | F9 | ⌥⌘R |
| Evaluate Expression — вычислить выражение | Alt+F8 | ⌥F8 |
| Остановить программу | красный квадрат Stop | красный квадрат Stop |

Что полезно помнить:

- Подсвеченная строка ещё **не** выполнена.
- Переменная появляется в Variables только после того, как выполнилась строка, где она объявлена.
- Breakpoint внутри функции срабатывает при каждом её вызове. Resume Program ведёт к следующей остановке.
- Если на строке несколько вызовов функций, Step Into предлагает выбрать, в какую войти.
- Step Out возвращает на ту же строку, откуда функция была вызвана, — она ещё не закончена.
- Если программа читает ввод, в режиме Debug вводи числа во вкладке Console окна отладки. Пока программа ждёт
  ввода, до breakpoint она не дойдёт.
- На Mac, если F7 и F8 меняют яркость или громкость, нажимай их вместе с Fn.

Решения пиши в заготовках `src/block6/TaskXX.java`.
